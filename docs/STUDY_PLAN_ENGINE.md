# Study Plan — Feature12 Local Beta

`/plan` works without AI. Inputs are goal, start/target dates, weekdays, daily available minutes, subjects/topics, explicit estimated required minutes, priority and student confidence. Days use calendar arithmetic independent of DST. The supported horizon is366 days,0–720 available minutes/day,1–100 topics,1–10080 required minutes/topic. Start must be today or later in the browser; a past target is rejected. Availability means discretionary study time after classes/sleep/other obligations, with today's remaining time entered by the user.

The deterministic engine sorts by earliest topic deadline, then higher priority, then lower self-assessment, then ID. It fills selected days in chronological order, in blocks of at most30 minutes. It never allocates more than the entered daily capacity or the topic's remaining demand. A zero budget or no weekdays produces no blocks and Over capacity. Missing deadlines use the target date; already-expired topic deadlines leave that demand unallocated. This is day-level budgeting, not clock-time scheduling or class-overlap resolution. An imported assignment preserves its exact deadline/timezone in provenance and derives its date in the browser's timezone; work on that date must finish before the stated deadline time. No invented exams, assignments or institutional rules are added.

Planned/Done/Skipped are editable. Reschedule retains Done blocks and subtracts their minutes from outstanding work, removes unfinished placements and repacks all unfinished demand (including Skipped and previously unallocated work) from the selected date. Done minutes on the same day reduce that day's available capacity. ID collision checks support out-of-order completion and repeated rescheduling. Insufficient remaining capacity stays visible, never silently discarded. Editing inputs invalidates the generated draft and disables Save until regeneration; saved storage changes only with explicit Save.

Memory and Planner are not read to create candidates until their respective opt-in is selected. Each candidate must then be chosen, reviewed and added. Imported Memory uses only the student's recorded subject/topic/confidence, confirmed weakness, mistakes and learning date; it does not infer a new weakness. Planner candidates are existing unfinished assignments or selected saved classes. Default60 minutes is explicitly an editable estimate, not an observed workload. Disabling a source removes its topics from the draft; Save after regeneration removes those copies from the saved plan, or Clear all removes the entire plan. Turning a checkbox off alone does not silently delete a previously saved plan.

Explicit Save, export and Clear all use `unipilot-study-plan-v1` localStorage, with schema and arithmetic validation on restore. There is no server transfer. Today's UniPilot displays only a valid saved Planned block on or after today; Done, Skipped and past blocks are not recommendations. Manual plan estimates, imported copies and goals can be deleted independently from the original Memory/Planner records. AI explanations and personalized optimization are not enabled or validated.

Tests cover duration/capacity, zero availability, one day/tomorrow/past deadlines, multiple priorities/confidences, rescheduling, invalid storage, opt-in/off, persistence, export, Today and five responsive widths. Feature12 is Local Beta; authenticated Live workflow and student quality evaluation remain NOT_TESTED.
